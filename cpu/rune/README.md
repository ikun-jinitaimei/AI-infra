# Rune：约束下的任务调度

## 问题与起点

根据公开任务模型、可用计算资源和依赖关系选择调度动作。

## 假设与修改

以剩余关键路径和资源约束排序，将同批 setup 成本分摊，内存仍按任务计算；不读取未来事件或隐藏状态。

## 验证与限制

18×64=1152 个官方本地场景全合法，337/337；另有 288 个参数扰动场景全合法。它是调度质量结果，不是 CPU 内核加速倍数。

## 代码与复现

本目录保留：policy.py。官方基线与接口需按[复现说明](../../docs/reproduction.md)获取。详细版本演进见[实验记录](../../docs/optimization-history.md)，数值与证据见[结果说明](../../docs/results.md)。

## 学习重点

调度要同时考虑资源、依赖、批处理收益和合法性；可以迁移到 serving 思考，但不是通用 LLM scheduler。

# 从 baseline 到结果：四个优化案例

这里的baseline有两种含义：官方起始实现，或本轮接手的已有实现。两者明确区分。历史实验不是完整的单变量消融，不能把累计收益全部归因于最后一个改动。

<a id="maimoe"></a>
## MaiMoe：重复工作比算术更值得先优化

**问题与对照。** 谱面处理需要解析、事件计算、摘要与渲染，并产生精确输出。对照是本轮接手版本，不是重新测量的官方零修改baseline。代码检查与阶段诊断提示解析、字符串和哈希路径值得优先处理；没有保存到本仓库的完整profiler调用图，因此不以某个占比作为确凿证据。

**假设。** 如果移除逐事件字符串流、避免构建无用对象并复用同tick的哈希前缀，就能减少分配和重复运算；随后再对摘要和背景像素使用ARM指令。

| 累计阶段 | 最大样例耗时 ms | 改动机制 |
|---|---:|---|
| 接手版本 | 3706.430 | 本轮比较起点 |
| 解析优化 | 1343.395 | 紧凑数据、减少字符串工作 |
| 硬件SHA | 1125.801 | ARMv8 SHA指令 |
| 局部排序与栈上事件 | 880.307 | 利用tick单调性，减少堆分配 |
| 缓冲与前缀复用 | 688.367 | 复用容量和共同前缀，非答案缓存 |
| 向量背景与直接输出 | 656.027 | NEON及减少中间复制 |
| 专用渲染 | 621.028 | 利用状态机不变量 |
| 编译调优筛选 | 615.435 | 历史筛选结果，非最终报分 |
| 最终独立复验 | 616.736593 | 正式口径均值 |

最终四组采用1次预热、3次测量，逐次官方checker验证。最终平均耗时摘录见 [maimoe-final.json](../benchmarks/evidence/maimoe-final.json)，重复测量样本也一并保留。2603个额外输入的差分测试及20001种长度的SHA对照记录在原实验日志中；这里不提供输入集，也不把这些检查等同于所有可能输入的证明。

**未采用。** 双事件交错哈希把最大样例降至605.018 ms，但另一组退化、总分降低；专用I/O线程与更少worker也未获稳定收益。

**学到什么。** 优先消除重复工作，再考虑更低层指令；不能只追一个样例。数据布局、分配、库调用与调度都可能是开销来源。

<a id="miniclash"></a>
## Miniclash：SIMD宽度与端到端收益

**问题与对照。** 原搜索路径逐个生成并筛选整数候选；对照为标量版本。独立候选执行相同的位运算，适合批处理，但分支存活率、寄存器压力和搜索随机性可能抵消收益。

| 阶段 | 固定种子微测量累计秒数 | 解读 |
|---|---:|---|
| 标量 | 27.5275 | 固定输入与搜索种子的比较 |
| 全部搜索块4路SIMD | 20.9690 | 与上述标量同轮对照 |
| 8路 | 19.3977 | 后续批宽筛选中的基准 |
| 两块16路 | 15.6385 | 后续同类固定种子筛选；不是所有版本同一轮统计 |

16路由多条128位NEON指令实现，不代表CPU具有512位向量指令。32路相对16路未显示实质收益，保留16路。

一次掩码归约优化在固定种子微测量中为54.1762→52.2270 s，但三组256任务端到端累计仅79.62→79.33 s，且候选两组更慢。不能由微测量声称稳定端到端加速，因此回退。

最终八组官方任务检查通过；随机搜索性能仍有波动。**学到什么：** 控制随机种子和交替测试顺序有助于比较内核，但应用级测量仍不可省略。

<a id="rsm"></a>
## RSM：短段固定开销与缓冲容量

**问题与对照。** 对变长分段计算softmax加权均值、标准差倒数和logsumexp。公开加速比相对官方baseline，不能与某个单case速度简单平均。原逐段路径重复进行DMA、Cast、归约和标量交互；开销判断主要来自源码结构与改动后的时间比较，而不是完整设备profiler证据。

**假设与实现。** 连续段共享输入搬运；将短段放入不同列lane，共享向量指令和归约，但保持各段独立max、归一化因子与结果；复用片上缓冲，减少HBM流量与标量读写。

| 阶段 | 公开综合加速比 | 改动 / 状态 |
|---|---:|---|
| v17 | 4.808745 | 多段输入缓存 |
| v18 | 不计 | 临时缓冲容量问题导致检查失败 |
| v19 | 4.946081 | 修复补齐容量，联合短段 |
| v20 | 5.227821 | 支持变长短段组批 |
| v21 | 5.256323 | 更宽组、缓冲复用、倒数复用 |
| v23 | 5.303054 | 跨步搬移、向量Gather |

v18按真实rows×D判定容量，但归约会补齐至2次幂，可能越过临时缓冲。v19改用足够大的已有缓冲。早期v16也包含相关缺陷，虽当轮通过，不能据此宣布对所有合法形状可靠；历史指标留作过程证据，不推荐该版。

v23是主验证版本。v25通过二分 `offsets[i]+16*i` 划分连续工作，期望缓解段长不均；16是启发式参数，无设备测试，可能退化。其保留价值是待验证假设，不是已实现收益。

**学到什么。** 存储容量必须按实际执行形状检查；组批减少固定开销，但需要同时考虑padding、UB存活期、同步与尾部。

## Accelerate：控制比较口径

计算每个查询相对所有中心的距离、点积和非线性响应。Python作为接口，核心C代码编译为共享库，通过OpenMP和NEON执行。查询分块复用中心数据，向量多项式减少数学库调用；范围上界扫描决定能否进入快速路径，极端输入保留通用路径。

同一轮早期筛选中，接手版4.6078 s，8查询libm版2.2900 s，8查询向量数学版1.6863 s。后续探索16查询、双精度预转换和范围检查外提。不同节点、不同作业的时间不串成严格的单一加速曲线。

最终采用官方三新进程取最大耗时：1178.474888 / 1055.040193 / 1091.169983 ms，正确性通过。D16补充对照直接距离优于范数分解，故保留直接距离；D16输入来自公开数据截取，不是隐藏正式case。

**学到什么。** 浮点近似需要误差与范围论证；跨节点时间差不能全部归因于代码。当前没有cache-miss计数器证据，因此“改善局部性”是设计机制，而不是已量化的miss下降。

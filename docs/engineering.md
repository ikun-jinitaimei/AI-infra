# 优化过程

## CPU：批量运算与减少重复工作

Accelerate以16个查询为批次，复用同一中心数据，使用128位NEON双精度累积距离和点积。对数学函数使用范围缩减和多项式，并以本次输入推导范围上界；不能证明范围安全时保留通用数学路径。转换、边界推导与实际计算均在调用内，不缓存答案。

Miniclash把候选搜索循环改为16路无符号SIMD，保留候选顺序及存活候选的标量验证。更大展开、固定重启、PGO与I/O调整没有稳定收益，未把单次最快微基准作为整体结论。

MaiMoe先定位解析开销，再消除逐事件字符串流和重复哈希前缀。ARM SHA指令实现用独立对照验证，NEON负责像素批量处理；调度采用实测选择的worker与读写方式。

Rune基于公开任务模型、当前可用节点和剩余关键路径决策。将同批setup成本分摊，内存仍逐任务计算；不读取未来事件或隐藏状态。

Blackhole与Mahjx保留已测版本的相对上游补丁，分别展示数据复用/向量化与精确剪枝/缓存/并行搜索，便于审阅实际改动。

## NPU：缩短短段固定开销

RSM从每段独立处理出发，先增加行搬运批量，再引入跨短段输入缓存、变长短段列lane组批，以及融合的softmax和矩归约。各段仍有独立最大值、归一化因子与输出。

v18曾出现补齐后的二阶临时缓冲容量不足；v19改用足够大的现有缓冲。这个问题说明容量必须按归约补齐后的形状计算，不能只检查真实元素数。v23是本仓库的本地完整验证版本。

最后v25在v24的向量Gather改动上使用 `W(i)=offsets[i]+16*i` 估计前i段工作量，按其下界给核心分配连续区间。边界函数单调，覆盖不重叠；但启发式权重未调优，单个超长段仍不能被此方法拆开。该候选没有设备验证，不作为已确认性能收益。

## LLM：运行环境先于参数调优

Stage1先解决容器HOME不可写与临时目录清理失败，再执行官方准确性和吞吐测试。可写HOME与共享内存临时目录属于运行条件修复，不是吞吐测量中的捷径。

Stage2依据实际镜像内A2文档检查TP8、EP、Ascend量化、专用tokenizer、MTP、decode图、异步调度及DSA-CP配置。静态兼容性审查不能证明模型启动成功、精度达标或显存足够，因此Stage2保留候选标记。

## Cheatsheet：边界描述也属于实现质量

保留已取得公开好结果的CSA指导，仅补充N=8192、128字行宽、R=8192需要14位计数、空掩码、小R与每次初始化条件。两例公开性能测试不能覆盖全部合法边界，压缩文本也不应删除算法必要约束。

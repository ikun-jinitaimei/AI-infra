# 从科研计算到 AI Systems

这是一条学习路线，不是已完成能力清单。

| 主题 | 本项目已有实践 | 下一步补齐 |
|---|---|---|
| Linux / HPC | 工具链、模块环境、作业资源、容器运行 | 写一份可迁移的环境清单，理解进程、线程、NUMA 与亲和性 |
| C/C++ / 编译 | GCC、架构参数、LTO、容器与数据表示优化 | 独立解释生命周期、未定义行为、别名与浮点优化语义 |
| Cache / memory | 分块、紧凑记录、复用、减少中间复制 | 以硬件计数器检验局部性假设，区分延迟与带宽限制 |
| SIMD | NEON 整数搜索、双精度运算、像素批处理 | 阅读编译器向量化报告与反汇编，理解寄存器压力 |
| OpenMP | 独立分支与归约并行、线程配置 | 测量强扩展、false sharing 和调度开销 |
| MPI | 单节点共享窗口、同步和归约 | 多节点扩展、通信量模型与数值归约顺序 |
| Profiling | 插桩与 A/B 实验设计 | perf 采样/计数器、阶段图、可比重复实验 |
| NPU kernels | 片上缓存、DMA、短段组批、归约与精度 | 设备 profiler、核负载可视化、独立复现性能变化 |
| LLM serving | 容器配置、运行条件修复、Stage1 验证 | 独立研究 KV cache、prefill/decode、batching 与尾延迟 |

向 AI Infra 迁移的是测量、数据移动、并行粒度、同步与数值约束的思考方式。CUDA/Triton、NCCL、分布式推理、post-training 和 RL 系统仍需要独立项目验证，不能由本项目推定已经掌握。

面试讲解可以从一个案例开始：画出数据流 → 说明计时边界 → 给出瓶颈假设 → 展示一处源码改动 → 解释对照与失败尝试 → 指出证据还不足的地方。优先选 MaiMoe 或 Miniclash，并能自己复述关键实现，而非只展示最终分数。
